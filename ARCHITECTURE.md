# Stronghold Mobile — архитектура

Присылай этот файл в начале каждой новой сессии — он даёт полный контекст проекта.

## Правила, которые нельзя нарушать

1. **Состояние только в `src/core/state.js`.** Никаких глобальных переменных по файлам.
2. **Модули общаются через `src/core/events.js`.** Прямые вызовы между зонами (экономика → военка) запрещены.
3. **Рендер ничего не считает.** `src/render/` только рисует то, что уже в state.
4. **Цифры — в `/data/*.json`, не в коде.** Новое здание = строчка в JSON.
5. **Один заход = один этап.** Не мешаем этапы между собой.

## Структура

```
index.html            оболочка, HUD-разметка, стили
data/                 buildings.json, units.json, balance.json
src/
  config.js           TILE, размер карты, TPS, лимиты
  core/
    state.js          всё состояние игры
    events.js         шина событий
    loop.js           фиксированный тик логики + отрисовка + время (день/месяц/год)
  world/
    map.js            сетка, местность, проходимость, occupied[]
    camera.js         drag/pinch/zoom, worldToScreen, screenToTile
    pathfinding.js    A* + очередь запросов (лимит на тик)
    walker.js         тестовая сущность (станет базой рабочего на этапе 2)
  render/
    renderer.js       слой местности (offscreen) + сущности + сетка
  ui/
    hud.js            показания, диагностика, кнопки
  economy/            пусто — этапы 1–6
  society/            пусто — этап 4
  military/           пусто — этапы 8–9
assets/               спрайты, UI, звуки
```

## Стройка (этап 1)

- `data/buildings.json` — все параметры зданий. Новое здание = запись в JSON
  плюс функция в `tools/gen_buildings.py`; кода трогать не надо
- `src/economy/buildings.js` — `checkPlace()` проверяет границы, занятость,
  тип местности, наличие леса рядом и ресурсы; `place()` списывает ресурсы
  и помечает клетки занятыми (поиск пути сразу это видит)
- `src/ui/buildpanel.js` — категория → здание → призрак → подтверждение.
  Подтверждение внизу экрана, чтобы палец не закрывал место постройки.
  После постановки предлагается поставить ещё одно такое же
- Спрайт здания масштабируется по ширине пятна застройки, якорь — нижняя грань

## Рабочие (этап 2)

`src/economy/workers.js` — один конечный автомат на все профессии:

```
toSource → working → toStore → toSource
```

- `assignJobs()` раз в секунду добирает рабочих из `state.population`
  в здания, где `def.workers > 0`. Не хватило людей — над зданием красный значок
- источник ищется от здания: лесопилке ближайшее непомеченное дерево,
  каменоломне ближайшая клетка скалы с подходом
- дерево помечается `taken`, чтобы двое не шли к одному стволу
- срубленное дерево удаляется из `map.decor`, на его месте остаётся пень
  в `map.stumps`; `regrowForest()` по событию `month` возвращает часть пней
  в лес — ресурс не бесконечный, но и не кончается навсегда
- если до цели не дойти, три попытки и пауза: иначе рабочий каждый тик
  просит новый маршрут и забивает очередь поиска пути

`src/economy/storage.js` — ресурс сам находит здание: сырьё на склад,
еда в амбар. Зерно и мука считаются сырьём и лежат на складе, в амбар идёт
только готовая еда — как в оригинале.

### Ферма (шаг 3.1)

- `growFields()` каждый тик подращивает поля: `growth` 0→3, спрайт берётся
  как `wheatfarm_<growth>`, поэтому поле видно на любой стадии
- на последней стадии у здания появляются `harvestsLeft` — фермер делает
  три ходки с зерном, после чего поле сбрасывается в стадию 0 и растёт заново
- поле зреет само, пока фермер несёт зерно: ходка и рост идут параллельно

### Мастерские (шаги 3.2–3.3)

Мельница и пекарня используют тот же автомат, только источник у них — склад:

```
склад с сырьём → своё здание → переработка → склад с готовым
```

Мука лежит на складе, хлеб уходит в амбар — маршрут выбирается автоматически
по типу ресурса. Оружейные мастерские этапа 6 подключатся сюда же.

### Навигация

Два помощника, оба возвращают `moving` / `arrived` / `failed`:

- `navToTile()` — к клетке карты (дерево, скала, борозда)
- `navTo()` — к зданию, причём маршрут ищется **сразу ко всем его входам**
  через `findPathAny()` (A* с несколькими целями)

Почему так: сначала рабочий шёл к ближайшему по прямой входу, тот оказывался
в тупике за лесом, маршрут не находился — и рабочий бесконечно бегал туда-обратно,
таская зерно на склад и обратно. Многоцелевой поиск решает это одним запросом.

Ещё два правила при постановке зданий:
- у здания должен быть хотя бы один подход (`hasApproach`)
- новая постройка не должна отрезать вход соседям (`blocksNeighbour`) —
  иначе игрок случайно замуровывает собственную мельницу

## Население (шаг 4.1)

`src/society/population.js`

- вместимость = число лачуг × 8; свободных мест нет — никто не придёт
- раз в игровой день: популярность выше 50 — приходит человек, ниже 50 — уходит
- пришедший становится сущностью `idler` и слоняется у донжона: население
  видно на карте, а не только цифрой в интерфейсе
- наём забирает праздного крестьянина с площади (`takeIdler`)
- уходят сначала праздные, и только если их нет — увольняется рабочий
- снесли жильё, людей больше мест — лишние уходят сами

Популярность пока держится на 55 (чуть выше нейтрали), чтобы игра стартовала.
Настоящий расчёт из еды, налогов и страха — шаги 4.2–4.4.

## Еда и настроение (шаги 4.2–4.3)

`src/society/food.js`

- паёк: нет / половина / обычный / двойной / тройной (0, 0.5, 1, 2, 3 порции
  в месяц на человека), вклад в настроение от −32 до +8
- раздача идёт **каждый день** и списывает еду пропорционально запасам, чтобы
  разнообразие держалось дольше, а не выедался один хлеб
- за каждый вид еды сверх первого +1 к настроению

`src/society/popularity.js`

- девять уровней налога от раздачи золота ×3 до грабительского
- раз в месяц: собираем налог (или раздаём, пока в казне есть чем платить),
  затем сдвигаем популярность на сумму факторов — еда, налог, страх, теснота
- популярность **копится**, а не считается с нуля: щедрость отыгрывается
  не мгновенно, и разорить доверие легче, чем вернуть

Проверка симуляцией: без налога замок заполняется до 32 человек за 3 месяца;
грабительский налог за 4 месяца выгоняет всех; тройной паёк с раздачей золота
поднимает настроение на +14 в месяц, и народ возвращается.

## Страх (шаг 4.4)

Шкала от −5 (ужас) до +5 (радость), сумма по всем постройкам:

| Пряники | | Кнуты | |
|---|---|---|---|
| Статуя | +1 | Позорный столб | −1 |
| Сад | +2 | Клетка | −2 |
| Фонтан | +3 | Виселица | −4 |

Два эффекта, направленных в разные стороны:

- популярность: `fearFactor × 2`, то есть от −10 до +10 в месяц
- скорость работы: `1 − fearFactor × 0.10`, то есть при −5 работают в полтора
  раза быстрее, при +5 — вдвое медленнее

Отсюда и весь выбор: злой лорд получает вдвое больше ресурсов, но народ
разбегается; добрый копит доверие и теряет в производстве. По симуляции:
виселица с клеткой дают −8 популярности в месяц и темп 1.50; фонтан с садом
и статуей — +14 в месяц и темп 0.50.

## Дичь и разнообразие еды (шаг 5.1)

`src/world/animals.js` — олени, кабаны, зайцы и тетерева из пака CraftPix.
Кадр 32×32, шесть кадров ходьбы, четыре направления.

- звери заводятся на лугах у кромки леса и бродят короткими перебежками
- охотник берёт ближайшего непомеченного зверя, идёт к нему (цель обновляется
  на лету — зверь-то ходит), бьёт и несёт мясо в амбар: олень 3, кабан 4,
  заяц и тетерев по 1
- раз в месяц поголовье восстанавливается до 14, так что выбить дичь совсем
  нельзя, но и охотиться бесконечно в одном месте не выйдет

Молочная ферма — мастерская без входного сырья: работник просто крутит цикл
и выдаёт сыр. Яблоневый сад устроен как пшеничное поле, но со своими стадиями
(голые деревья → цвет → завязь → яблоки) и более долгим созреванием.

Смысл шага — **разнообразие**: за каждый вид еды сверх первого народ доплачивает
+1 к настроению. По симуляции четыре вида (хлеб, мясо, сыр, яблоки) дают
+3 в месяц сверх пайка, и популярность растёт вдвое быстрее.

## Эль (шаг 5.2)

Цепочка: **хмельник → пивоварня → склад → таверна → народ**.

`src/society/ale.js` считает не запас, а **охват**: одна таверна обслуживает
20 человек, бочка держит её четыре дня. Настроение — от +1 до +8 по доле
народа, получившего эль. Поэтому на растущий замок таверны приходится ставить
по кварталам, а не одну большую — как в оригинале.

Таверна в коде — мастерская без выхода: разносчик приносит бочку со склада,
она встаёт в погреб (`b.ale`), а дневная раздача её тратит.

## Ориентация

Игра идёт **в лежачем положении**: в манифесте `sensorLandscape`, в вёрстке
отдельная ветка `@media (orientation:landscape)`. Логика та же, меняются
только пропорции интерфейса:

- верхняя строка 34 px вместо 44, нижние кнопки 48 вместо 60
- панель строительства не выше 44% высоты, карточки в две строки с переносом
- при высоте экрана меньше 400 px диагностика прячется совсем

Причина простая: лёжа высота экрана дорогая, а ширина дешёвая. На типичном
телефоне лёжа видно 64×29 клеток против 29×64 стоя — замок наконец
помещается целиком.

## Стены (шаг 7.1)

Стены — **не здания, а отдельный слой сетки** `map.walls`: одна клетка —
один байт. Так дешевле по памяти и проще считать стыковку.

- спрайт выбирается по маске соседей (N=1 E=2 S=4 W=8), 16 вариантов
  на материал: генератор `tools/gen_walls.py`
- тайл стены 32×48 — нижние 32 это клетка, верхние 16 высота кладки,
  поэтому стена перекрывает то, что за ней, наравне со зданиями
- строительство **линией**: палец ведёт от начала к концу, линия идёт
  по прямой с одним изломом; ставится столько клеток, на сколько хватит
  материала, в минус уйти нельзя
- пока чертится стена, один палец не двигает карту (`camera.lockDrag`),
  двумя пальцами зум и панорама работают как обычно
- стены перекрывают проход, поиск пути это сразу видит

## Приказы (шаг 8.2)

Выделение рамкой на телефоне не работает, поэтому сделано иначе: в панели
войск кнопки **«Все (7)», «Копейщик 4», «Лучник 3»** — тапнул, отряд выбран,
дальше один тап по карте.

- тап по земле — **идти**: отряд раскладывается спиралью вокруг точки,
  чтобы не толпиться в одной клетке
- тап по башне — **встать на пост**: сколько влезет по `garrison`,
  лишние остаются на месте
- «Вольно» возвращает солдат к казарме

`effectiveRange()` считает дальность с учётом поста: лучник на круглой башне
бьёт на 7+3 вместо 7. Отсюда смысл держать стрелков на башнях, а не в поле.

Выделенные обведены кольцом под ногами.

## Наём войск (шаг 8.1)

Формула из оригинала: **свободный человек + оружие из арсенала + золото**.
Не хватило любого из трёх — солдата не будет, и кнопка прямо пишет чего:
«Нет: копьё», «Не хватает золота», «Нет свободных людей».

| Юнит | Нужно | Золото | HP | Урон | Дальность |
|---|---|---|---|---|---|
| Копейщик | копьё | 8 | 40 | 6 | — |
| Лучник | лук | 12 | 30 | 5 | 7 |
| Арбалетчик | лук + кожаный доспех | 20 | 45 | 14 | 6 |
| Пикинёр | копьё + доспех | 20 | 90 | 9 | — |
| Мечник | меч + доспех | 40 | 120 | 16 | — |

Список нарочно урезан до тех, кого наше производство может снарядить.
Спрайты переиспользуются: пикинёр рисуется копейщиком, арбалетчик лучником.

Нанятый солдат отнимает человека у населения — армия и экономика делят
один и тот же народ, как и должно быть.

## Ров и ловушки (шаг 7.3)

Ключевое отличие рва от стены: **ров не перекрывает путь, а замедляет**.
У карты появился `moveCost(x, y)` — сухой ров вчетверо дороже обычной клетки,
смоляной втрое, — и поиск пути это учитывает. Атакующие вязнут под обстрелом
со стен, но при желании могут лезть напролом. Самотест проверяет, что
маршрут предпочитает обойти ров, а не идти по нему.

Смоляной ров стоит смолы (по бочке за клетку) и **поджигается**: огонь
разбегается по всей связной луже, смола выгорает, яма остаётся сухим рвом.
Очаги горят несколько секунд и гаснут; урон по тем, кто в огне, добавится
на этапе 9 вместе с осадой.

Волчья яма — ловушка с флагом `passable`: на неё можно наступить, иначе
она бессмысленна. Колодец пока просто стоит, его час придёт с пожарами.

## Ворота и башни (шаг 7.2)

Появился флаг `passable` у здания: клетки числятся занятыми, чтобы на них
нельзя было строить, но люди сквозь них ходят. Для этого у карты отдельный
слой `map.passable`, а `walkable()` проверяет его перед `occupied`.

Ворота ставятся **прямо в линию стены** — стена под ними убирается сама.
Самотест проверяет всю связку: стена поперёк карты перекрывает путь,
ворота его восстанавливают, а строить на воротах нельзя.

Башни — обычные непроходимые здания, но с полями на будущее:
`garrison` (сколько стрелков помещается) и `rangeBonus` (прибавка к дальности),
у квадратной ещё `engines` — на неё встанут баллиста и мангонель на этапе 9.

| Башня | Гарнизон | Дальность | Камень |
|---|---|---|---|
| Сторожевая 2×2 | 4 | +2 | 15 |
| Круглая 3×3 | 8 | +3 | 30 |
| Квадратная 3×3 | 10 | +3 | 35 |

## Оружие (этап 6)

Три склада вместо двух: сырьё на **склад**, еда в **амбар**, оружие
и доспехи в **арсенал**. Маршрут выбирается по типу ресурса автоматически.

| Мастерская | Из чего | Что делает |
|---|---|---|
| Копейщик-токарь | дерево | копьё |
| Лучный мастер | дерево | лук |
| Кузница | железо | меч |
| Оружейник | железо | металлический доспех |
| Кожевник | — | кожаный доспех, нужна молочная ферма |

У кожевника появилось новое правило постройки: `needsBuilding` — здание
требует, чтобы в замке уже стояло другое. Проверяется в `checkPlace`,
причина отказа так и пишется: «Сначала нужна: Молочная ферма».

Оружие продаётся на рынке дороже сырья (меч 58 против железа 25) — отсюда
и берётся классическая мирная стратегия: гнать оружие на продажу, а еду
скупать. Самотест это проверяет отдельно.

## Рынок (шаг 5.4)

`src/economy/market.js` — двенадцать товаров с базовой ценой. Покупка идёт
с наценкой ×1.25, продажа со скидкой ×0.7, поэтому круг «купил-продал»
всегда убыточен: бесконечных денег из воздуха не будет (это отдельно
проверяется в самотесте).

Отсюда вырастает мирная стратегия: гнать дорогой товар (эль 20, железо 25)
и скупать дешёвый хлеб. Панель под палец: слева запас, справа две крупные
кнопки с итоговой суммой, переключатель количества 1 / 5 / 20.

## Самопроверка

`node tools/selftest.mjs` — 160 проверок без браузера: карта, валидность
маршрутов, все правила постройки, три игровых года подряд с ежедневным
контролем инвариантов, голод и налоги, склады, рынок, целостность данных
зданий. Гонять после каждого этапа.

## Связность замка

`cutsOff()` при постановке проверяет заливкой от донжона, что ни одно здание
не осталось отрезанным. Причина: во время сборки шага 5.2 хмельник оказался
за стеной из построек, пути к складу не было, и рабочий навсегда встал
с хмелем в руках. Теперь такая постройка просто не ставится — «Отрежет путь».

## Сортировка по глубине

Всё, что стоит на земле (декор и юниты), собирается в один список и сортируется
по `y` перед отрисовкой: кто ниже по карте — тот рисуется поверх. Якорь у всех
общий — низ спрайта на нижней грани своей клетки. Без этого юнит закрывает
дерево, за которым стоит.

## Контракт сущности

Любой ходящий объект (рабочий, солдат, зверь) имеет минимум:

```js
{ id, type, role, x, y, speed, path, pathStep, pathPending, dir, frame, anim }
```

`x`/`y` — в клетках, дробные. Движение по `path` делает модуль-владелец, маршрут просит через `requestPath(entity, tx, ty)`.

## Ассеты

Юниты генерируются кодом. Рабочая версия — `tools/gen_sprites_v4.py`:
64x64, 4 направления, 8 кадров ходьбы → `assets/sprites/units64.png`.
Новый юнит = запись в `ROLES` (палитра, головной убор, оружие, щит, кольчуга).
Версии v1 (16), v2 (24), v3 (32) оставлены для сравнения.

**Масштаб зафиксирован:** TILE = 32, кадр юнита = 64 (фигура занимает две клетки
по высоте). Это совпадает с паками CraftPix: мелкие объекты 16, средние 32,
деревья и руины 64–128, звери — кадр 32.

Паки лежат в `assets/craftpix/`: trees, rocks, bushes, ruins, animals, character.
Отобраны только PNG без встроенной тени — тень рисуем сами, иначе она не ложится
на разный рельеф. Имена файлов, которые реально используются, перечислены
в `src/render/sprites.js` (TREES, ROCKS, BUSHES) — менять набор там.

Плоская заливка местности временная, до появления тайлсета. Границы между
типами размываются дизерингом в `Renderer.buildTerrain()` — четыре ряда пикселей
с убывающей плотностью, иначе карта выглядит лестницей из квадратов.

## Расстановка декора

`GameMap.buildDecor()`. Правила, из-за которых карта не превращается в кашу:

- клетки перебираются в случайном порядке, иначе объекты встают рядами
- «синий шум»: крупные деревья держат дистанцию в клетку, мелкие могут стоять
  вплотную — так кроны смыкаются в массив
- `depthMap()` считает, насколько клетка утоплена внутрь зоны: в глубине леса
  деревья крупные, по кромке мелкие, край читается мягко
- камни садятся по кромке скалы, в центре пусто
- кусты только у кромки леса, не по всему полю
- одна порода деревьев на карту плюс редкий плодовый акцент; смешивать породы
  нельзя, лес выглядит винегретом

Инструмент проверки: `tools/scene_preview.py` рисует кадр из настоящих данных
карты (сначала `node` выгружает world.json), чтобы оценивать расстановку
не запуская игру.

Стиль и размер тайла ещё не зафиксированы. Пока местность рисуется цветными квадратами, сущности — квадратиками. Когда придут спрайты: меняем `CONFIG.TILE`, добавляем `src/render/sprites.js`, правим `Renderer.buildTerrain()` и `drawEntities()`. Остальной код не трогаем.

## Проверка производительности (этап 0)

Кнопки «+100 / +500 юнитов» спавнят ходоков со случайными маршрутами через A*.
Смотрим на FPS при 300 и при 1000. Решение по итогу:

- 55–60 FPS при 1000 → Canvas 2D хватит до конца проекта
- 30–45 при 300 → оптимизируем (реже пересчитываем пути, режем отрисовку)
- ниже 30 при 300 → переходим на WebGL-рендер сразу, пока код маленький
